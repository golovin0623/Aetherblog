§ 00 · Audit

先承认底子，再直面差距

重设计不是推翻。现有 v1 的骨架 —— 分组、乐观发送、防竞态 —— 都值得保留；缺的是把「消息软件的肌肉记忆」补齐。

✓ 已经做对的

  • iMessage 式消息分组 —— 同发送者 5 分钟内折叠头像、仅末条带尾角 MessageThread.tsx
  • 乐观发送 + clientMsgId 去重，切会话防竞态三处显式守卫
  • WebSocket 单连接：指数退避 1s→15s、心跳 25s、typing 4s 过期
  • 打字气泡 / 在线点 / 日期分隔 / 回到最新 均已在
  • 骨架屏加载（零 spinner，守住设计红线 §3.6）
  • 皮肤偏好后端已通：chat_settings.bubble_style / accent_color

○ 与微信 / Telegram 的真实差距

  • 零表情体系 —— 没有 emoji 面板、没有贴纸、没有消息回应
  • 回复链路半途而废 —— DTO 已有 replyToId，但没有任何 UI
  • 已读回执白白丢掉 —— WS 已下发 read 事件，前端未消费
  • 图片体验裸奔 —— 无粘贴/拖拽、无发送前预览、无进度、无灯箱
  • 消息无操作面 —— 不能右键/长按，无复制、撤回、编辑、转发
  • 提示链断裂 —— 无跨会话 toast、无标题闪烁、无声音、导航无总未读
  • 没有联系人视图 —— 只有会话列表，成员与智能体无处可寻
  • 会话不可管理 —— 无置顶、免打扰(muted 字段闲置)、无会话信息面板
「差距不在视觉，在肌肉记忆 —— 用户在微信里养成的每一个下意识动作（长按、引用、+1、拍图即发），在这里都落了空。」 诊断结论 · 基于 team-chat 全部 10 个源文件与后端 18 个端点

§ 01 · Stance

向三家各借一样，其余坚决不借

「对标微信」不等于「变成微信」。先定义清楚这间对话空间是给谁用的：一个写作团队 + 一群常驻智能体，没有陌生人社交。

功能定义（这是用户点名的第一个缺口）：AetherBlog 的对话空间是创作团队的协作信道，不是通讯录社交产品。因此不做好友申请 / 验证 / 陌生人会话 —— 联系人即「团队成员目录 + 智能体席位」，由现有 /members 与 /agents 两个端点聚合而成，一行后端都不用加。砍掉伪需求，才有力气把真需求做到微信级。

参照借来的肌肉记忆明确不借的
微信 拍图即发的轻、〔草稿〕红字、消息撤回后的「重新编辑」、免打扰会话只亮灰点不计数、「以下为新消息」分隔线 灰绿工具感、朋友圈、公众号层级、把 IM 做成操作系统
Telegram 回复引用可点击跳回原文、消息编辑与 ✓✓ 已读、↑ 编辑上一条、贴纸作为一等公民、流畅的入场动效 频道/机器人市场的复杂度、无限自定义主题商店
QQ 消息回应（+1 表情聚合）、群成员身份标识、活跃的群空间氛围 等级/勋章/装扮体系、彩色气泡的视觉噪音
「微信解决的是十亿人的最大公约数，我们解决的是一张书桌旁六个人（其中两位是 AI）的默契。规模不同，克制的方式也不同 —— 但『顺手』的标准是同一个。」 设计立场 · Aether Codex 三张力之「禅 × 锐」在 IM 场景的落点

Aether 独有的一件事：智能体不是挂件，是同席者。文澜（写作助手）与阿代（代码评审）以成员身份出现在联系人、群聊与 @ 提及里；它们的回复以 ink-bleed 墨渗动效流式书写 —— 这是设计系统签名时刻 #5「AI 工坊」在对话空间的直接延伸，也是微信永远不会有的一幕。

§ 03 · Gap Decisions

用户点名的每一个缺口，各给一个决定

每张卡片对应任务描述中的一项欠缺：现状一句话，方案三五条，原型里可当场验证。

01

功能定义

现状：定位含糊 —— 像微信但什么都少一截，像工具又没有工具的锐度。

  • 一句话定位：创作团队 + 常驻智能体的协作信道，无陌生人社交。
  • 砍掉好友申请链路，联系人 = 成员目录 + 智能体席位（零新后端）。
  • 智能体升为同席者：可 @、可私聊、回复流式墨渗。

原型 · 联系人 tab → 点击文澜发起私聊

02

好友列表 / 联系人

现状：不存在 —— 想找人只能翻会话流水，找智能体要进过会话的横杠。

  • Rail 第二 tab：星标 / 团队成员 / 智能体 三组卡片。
  • 成员卡：头像 · 在线 · 角色（OWNER/ADMIN/MEMBER/AGENT 现成字段）。
  • 点击即 openDirect(userId) —— 复用现有端点。

原型 · 左栏第二个图标

03

表情包支持

现状：零 —— 输入框只认纯文本，一个 emoji 面板都没有。

  • 三层体系（§4 详述）：emoji 字符 → 消息回应 → 「星灵」贴纸包。
  • 贴纸走 attachmentMeta.sticker 协议 —— P0 零后端落地。
  • 最近使用 localStorage 持久，面板 240ms overlay 弹出。

原型 · 输入框左侧笑脸 → 星灵贴纸

04

图片发送

现状：裸 input 直传 —— 无预览无进度无灯箱，粘贴拖拽全不支持。

  • 四入口：按钮 / 粘贴 / 拖拽（全帧遮罩）/ 移动端拍摄。
  • 发送前托盘预览 + 进度环；多图 2×2 九宫格式排布。
  • 灯箱：缩放 · 左右切换 · 渐进占位（blurhash 色块 → 原图）。

原型 · 直接拖一张图进对话

05

交互逻辑

现状：消息是死的 —— 悬停无反应，右键是浏览器菜单，长按无事发生。

  • 悬停快捷条：三枚高频回应 + 回复 + 更多，260ms 浮现。
  • 右键 / 长按 480ms：回复 · 复制 · 转发 · 收藏 · 编辑 · 撤回。
  • 撤回 2 分钟窗口，留「重新编辑」；编辑后缀 (已编辑)。
  • 引用块可点击 → 滚回原文 + 极光闪烁两次定位。

原型 · 右键任意消息，或导演台 ④

06

对话空间

现状：只有消息流 —— 无信息面板、无媒体墙、无公告、无成员管理入口。

  • 右缘信息面板：公告卡 · 成员列表 · 媒体墙 · 会话偏好。
  • 置顶 / 免打扰开关直连 chat_members（muted 字段已闲置一版）。
  • 气泡样式三档就地切换，写回现有 PUT /settings。

原型 · 会话头部最右图标

07

消息提示

现状：断链 —— 除列表徽标外一片寂静：无 toast、无标题闪烁、无声音、无 @。

  • 五级提示面（§6）：气泡回执 → 会话徽标 → 总未读 → 页内 toast → 系统级。
  • @我 用信号红徽标越过免打扰；免打扰会话只亮灰点。
  • 声音是合成的双音「墨滴」，默认关，尊重 reduced-motion。

原型 · 导演台 ① 收到消息

08

页面与细节

现状：能用但无质感 —— 无滚动阴影、无发送微动、时间戳排版随意。

  • 日期分隔用典籍 § 记号；时间戳一律 Geist Mono + tnum。
  • 发送时气泡从输入框弹入（260ms spring）；回应 chip 有 pop。
  • 滚动阴影、聚焦光环、连接状态呼吸点 —— 全部走 token 曲线。

原型 · 发一条消息看回执三态

§ 04 · Expression System

表情不是一个面板，是三层语言

微信教会用户：轻的情绪用 +1，重的情绪用贴纸。三层各有语义，不互相替代。

层语义形态数据面
① Emoji 字符行内情绪，随文字走面板 8 类 + 最近使用，插入光标处纯文本，零改动
② 消息回应「已阅 + 态度」，不打断对话流悬停快捷条 / 菜单回应排；气泡下聚合 chip，同表情计数P1：chat_message_reactions 表 + WS 事件
③ 星灵贴纸完整的情绪句子，独立成条108px 无气泡渲染，hover 微倾P0：IMAGE + attachmentMeta.sticker 协议

「星灵 Aeti」原创贴纸包 · 首期八枚。角色取自站点的极光光源本体 —— 一缕会发光的小彗尾，除了眼睛不需要五官，全部情绪由体态与光完成。SVG 矢量单枚 <2KB，naming 走 aeti/<slug>，token 渐变确保暗亮两主题同样成立；后续以 Lottie 升级动态版而不换资产协议。

§ 05 · Rich Media Pipeline

从「选择文件」到「拍图即发」

图片是 IM 第二语言。管线六步，每一步都有可感知的状态 —— 没有一步是黑盒等待。

捕获 —— 四条入口一个终点

工具按钮 / paste 剪贴板 / 全帧拖拽遮罩 / 移动端 capture。全部汇入同一个「待发托盘」，多图排队，可单张移除。

压缩 —— 发送前，不是发送后

Canvas 重采样至长边 ≤2560px、WebP q0.82，EXIF 方向纠正后剥离（隐私）。1MB 以下原图直传。压缩在 Worker 内完成，不阻塞输入。

上传 —— 进度环可见

复用 POST /chat/attachments，改用 XHR 以拿到 progress 事件驱动 SVG 进度环；失败留在托盘可重试，不产生幽灵消息。

占位 —— 先给颜色，再给像素

上传时同步计算 blurhash（或 4×3 均色矩阵）写入 attachmentMeta；接收端先渲染极光色块占位，图片 onload 后 520ms 淡入 —— 列表永不跳动。

排布 —— 九宫语义

单图按原比例最大 300px；2–4 图方格网格；宽高比进 attachmentMeta 预置占位尺寸。会话列表预览显示「[图片]」。

查看 —— 灯箱终点

点击开灯箱：深空遮罩 + 24px 模糊，左右键切换同会话图片，Esc 关闭；媒体墙（信息面板）共用同一灯箱。语音消息同理升级：MediaRecorder 采样 28 段波形写入 meta，播放时波形逐段点亮。

§ 06 · Notification Ladder

五级提示面 × 一条打扰红线

提示设计的本质是分配注意力：越远的层级越克制，@我 是唯一可以越权的信号。

级提示面触发形态免打扰时
L1气泡回执我方消息状态变化钟面 → ✓ → 极光 ✓✓（读 WS read 事件）不受影响
L2会话徽标非活动会话新消息极光数字 pill；@我 换信号红 @ 徽标灰点，不计数
L3导航总数全局未读合计Rail 徽标 + BlogHeader「对话」入口同步不计入
L4页内 Toast页面可见但会话不活跃右上滑入 420ms，头像+摘要+快捷回复，5s 自散，点击跳转不弹
L5系统级页面不可见标题闪烁「(2) 新消息」+ Notification API（授权卡在设置里，不劫持首访）+ 合成墨滴音仅 @我 穿透

声音刻意不用素材文件：Web Audio 两枚正弦音（E5→B5，180ms）合成「墨滴入砚」，与视觉系统同源的克制。默认关闭；prefers-reduced-motion 下 L4/L5 的动画降为直接出现。

§ 08 · State Machines

消息一生，连接一生

把 v1 埋在组件里的隐式状态抬成显式契约 —— 每个态都有可见形态，没有静默失败。

消息态进入条件可见形态出口
draft输入未发送 / 切走会话列表预览 [草稿] 红字 + 正文发送 / 清空
pending乐观插入，REST 未返回钟面图标微脉动ack → sent；超时/失败 → failed
sent / delivered服务端落库单 ✓（群聊终态）read 事件 → read
readWS read 回执极光 ✓✓（私聊）终态
failedREST 报错 / 断网出队信号红 ! + 「重试」链接，不吞消息重试 → pending
edited2min 内编辑（P1 端点）正文更新 + (已编辑) 后缀可再编辑
recalled2min 内撤回（P1 端点）系统行「你撤回了一条消息 · 重新编辑」重新编辑回填输入框
连接态形态行为
live绿色呼吸点「实时」心跳 25s（沿用 useChatSocket）
reconnecting琥珀「重连中 · Ns」倒计时指数退避 1s→15s；期间发送入本地队列，Composer 不禁用
restoredToast「连接恢复，补拉 N 条」按最后消息 ID 增量补拉，队列自动重发
offline灰点「离线」+ 顶部静默条只读历史可滚动；恢复后同 restored
