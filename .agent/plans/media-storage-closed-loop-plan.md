# 媒体上传、存储切换与备份闭环整改计划

## 目标

把媒体能力收敛为一条可解释、可运维、对文章内容稳定的闭环:

- 主存储决定新上传文件的落点。
- 备份目标独立于主存储,用于镜像、灾备和跨存储迁移准备。
- 自动备份开启后,新上传文件自动进入备份队列。
- 切换备份目标后,全量同步能识别旧目标备份并重新入队。
- 文章编辑器插入稳定媒体访问地址,后续本地/云存储切换不再把文章图片绑定死到某个瞬时 URL。

## 现状断点

1. 上传成功只创建 `media_files` 记录,不会因为 `storage.sync.auto_enabled=true` 自动入队备份。
2. `EnqueueAllUnsynced` 只看 `sync_status`,把所有 `SYNCED` 行跳过,切换备份目标后不会重建新目标镜像。
3. 文章编辑器上传图片后写入 `cdnUrl` 或 `fileUrl` 直连地址,后续备份完成或存储策略变化不会反映到已写入 Markdown 的图片。
4. 前端编辑器仍允许 `image/svg+xml`,但后端已明确拒绝 SVG,用户体验与安全策略不一致。

## 落地方案

1. 后端给每个媒体文件返回稳定公共访问地址: `/api/v1/public/media/{id}`。
2. 公共访问路由按当前媒体状态解析最佳地址:
   - 本地主文件且备份已 `SYNCED` 时跳转到 `backup_url`;
   - 否则优先跳转 `cdn_url`;
   - 再回退到当前主存储按 `file_path` 生成的 URL。
3. `/api/uploads/{key}` 不再只是静态文件入口,而是先反查媒体记录;能命中时同样按当前策略跳转,查不到时继续本地静态兜底。
4. 管理端文章编辑器上传图片后优先插入 `publicUrl`,让文章内容绑定媒体记录而不是绑定某个对象存储 URL。
5. `MediaHandler` 在上传成功后调用备份调度器,自动备份开启时将新文件入队。
6. 修正备份入队筛选:只有“已同步到当前目标”的记录跳过,已同步到旧目标的记录必须重新入队。
7. 前端类型补齐 `MISSING` 状态与 `publicUrl`,并移除 SVG 默认允许项。

## 验收标准

- 新上传图片的接口响应含 `publicUrl`。
- 文章编辑器插入 Markdown 时使用 `publicUrl`。
- 历史文章中的 `/api/uploads/{key}` 本地图片可通过 catalog 反查当前最佳访问地址,无 catalog 时仍能本地静态访问。
- 自动备份开启时,上传成功会尝试入队且不阻断上传主流程。
- 切换备份目标后,历史 `SYNCED` 到旧目标的媒体能被全量同步重新选中。
- Go 后端相关测试通过,前端 type-check 不因类型漂移失败。
