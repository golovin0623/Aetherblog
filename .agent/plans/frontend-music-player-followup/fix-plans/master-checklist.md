# 前台音乐卡片与浮岛联动修复总清单

## 目标

让个人音乐卡片、灵动音乐元、迷你播放器和沉浸播放器成为同一个连续播放对象：卡片可见时不重复浮出播放器，离开播放卡片后才出现最小入口，回到卡片立即自然隐去；三档形态沿同一几何锚点连续变形。

## 实施顺序

1. 为 `SeekBar` 增加只读进度态；博客内嵌音乐卡片始终只展示进度，让指针穿透给外层卡片轮播；精确 seek 留给浮岛与完整播放器。
2. 在播放上下文中建立多播放面可见性注册，个人/首页音乐卡片使用带安全边距的 `IntersectionObserver` 上报。
3. 更新播放器表面状态机：显式沉浸意图优先；其余浮层在页内播放面可见时必须为 Hidden；完全离开后从 orb 开始。
4. 删除“首次播放自动打开 compact”规则；重新进入卡片时把浮层密度复位为 orb，避免再次离开时弹出大卡片。
5. 用一个稳定的浮动外壳承载 orb / compact，并让同一张封面节点在外壳内部保持连续身份；封面只做一次 position projection，内容分层淡入；compact 使用集成式收起图标，不再保留顶边握柄。
6. 给 compact / immersive 共享布局标识，使最大化与还原沿左下角锚点连续过渡；Reduced Motion 保持即时但可理解的显隐。
7. 把封面中心设为 orb/compact 的共同形变原点；封面从 52px 圆形连续生长到 64px 系统圆角封面；父外壳与封面必须复用同一个设计系统 motion preset，禁止两套弹簧各自运动。
8. 收起时由内容实际退出完成事件驱动外壳反向形变，不使用固定计时器；compact 使用固定终态高度，避免退出内容后先缩一次、随后再缩为 orb 的双重轨迹。
9. 前台 compact 保持 16px 四边安全留白和固定 64px 封面节奏；后台移动端保持 16px、桌面 compact/expanded 使用 24px 卡片章节留白，错误态同步同一边界。
10. 把前台外壳从仅尺寸投影改为完整位置+尺寸投影，使用 Motion 的左下原点，并让实际图片 inset 与封面外框共用同一 motion preset；源代码门禁只作为结构约束，另做真实浏览器逐帧轨迹验证。
11. 后台桌面 minimized 改为 352px 可见长胶囊、44px 完整内嵌封面和 32px 轻量播放圆环；compact 使用左右等宽的三列网格把 transport 锁在几何中心，并把进度条从桌面主内容流中移出；详情态改为双侧稳定滚动槽。

## 验收标准

- [x] 从个人/音乐卡片的进度轨道起手左右滑动可以切卡，轨道为只读 `progressbar` 且不会改变进度。
- [x] 卡片内点击播放只更新卡片自身状态，不出现 orb、compact 或沉浸层。
- [x] 播放卡片任一部分仍在带 24px 缓冲的视区内时，全局浮层隐藏；完全离开并经过 160ms 稳定窗口后仅出现 orb。
- [x] 卡片重新进入缓冲视区时浮层立即开始淡出；离开后不会恢复成先前展开的 compact。
- [x] orb → compact → immersive → compact → orb 都沿同一左下锚点连续改变尺寸与圆角，没有先消失再从另一处弹出的视觉断点。
- [x] compact 使用封面、标题、进度和对称 transport；收起入口为 44px 集成图标，不存在额外顶边握柄。
- [x] 前台、后台、紧凑、展开和移动端源码均不存在顶边握把/拖动条；拖拽由卡片表面与密度图标承担。
- [x] 父外壳与唯一封面节点共用同一套设计系统弹簧；逆向收起由内容真实退场完成事件驱动，源码不存在用于猜测结束时刻的 compact 定时器。
- [x] compact 终态使用固定高度，内容退场阶段不会先缩成中间尺寸；后台移动端为 16px、桌面端为 24px 对称留白。
- [x] 前台 shell 展开首帧不发生 200px 级位置瞬移，left/bottom 锚点全程稳定，实际图片与外框沿同一时间轴正反向运行。
- [x] 后台 minimized 可见胶囊 352×60px、封面 44px 且完整内嵌、播放可见圆环 32px/触控区 44px；compact 主播放键与 520px 卡片几何中心误差不超过 1px。
- [x] 320、360、390、768、1280 宽度无溢出、圆角裁切或触控区缩小。
- [x] compact 交互节点的 DOM、读屏和键盘焦点顺序与实际从上到下的视觉顺序一致，不依赖 CSS `order` 反排。
- [x] 相关 Vitest、Blog/Admin type-check、双端 lint、PostCSS、生产构建与 Chromium 动效/几何门禁通过。
