# 灵境（移动端）对齐差距分析报告

## 目标
- 将 `apps/blog/app/agent/workspace` 的移动端视觉与交互从“基础可用”升级为“高密度、低打扰、强反馈”的工作台体验。
- 品牌文案从“Agent”升级为“灵境”（仅使用内部命名，不出现外部产品对齐字样）。
- 修复“模型选择后实际请求不稳定生效”的体验问题。

## 现状差距（移动端）
1. **品牌语义不统一**：页面元信息与若干入口文案仍为 Agent，无法形成“灵境”心智。
2. **移动端控制区层级偏弱**：模型选择虽可用，但缺少“当前会话生效模型”的明确状态提示。
3. **模型生效链路可感知性不足**：用户切换模型后，若紧接发送，容易感知为“没有切换成功”。
4. **移动体验反馈颗粒度不够**：控制按钮触发后缺少即时状态映射（当前模型标签、按钮说明）。

## 根因分析
- 模型选择状态仅写入 `sessions`，发送时依赖 `activeSession` 快照；快速切换后立刻发送时，用户可能观察到“模型未切换”的结果（状态同步窗口导致的体感问题）。
- 交互层没有将“当前生效模型”做显式、即时、连续反馈，用户难判断是否已经应用到下一次请求。

## 对齐策略
1. **品牌升级**：工作台元信息从 `Agent` 改为 `灵境`。
2. **状态前置**：在工作台维护当前会话模型覆盖状态 `sessionModelOverride`，切换模型时即时更新。
3. **发送链路收敛**：发送请求优先使用 `sessionModelOverride`（并回退到会话存档），确保本轮请求使用用户最后一次选择。
4. **移动端反馈增强**：模型按钮在紧凑模式显示“模型”前缀，明确它是会话级控制项。

## 验收标准
- 切换模型后立即发送，请求 payload 中 `modelId/providerCode` 与最新选择一致。
- 移动端模型控件可快速识别、触控区域不小于 44x44（已有布局保持）。
- 工作台标题与关键文案使用“灵境”，无“对齐某产品”字样。
