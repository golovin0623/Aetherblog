# 移动端个人 / 音乐卡片首帧布局修复

## 分诊

- 严重度：P1（移动端主页面核心卡片出现持续裁切与切换过程二次跳变）。
- 证据：真机截图中，资料卡当前页缺失内面板底边；音乐卡滑入但分页尚未提交时同样缺失底边，提交为音乐页后才恢复。
- 根因：三列轮播轨道未显式约束唯一网格行，Grid 的自动最小尺寸会被当前资料卡的社交区撑高；舞台使用圆角裁切，导致超出舞台的面板底边被隐藏。切页完成后资料卡社交区卸载，行高重新计算，于是出现“先遮挡、后恢复”。

## 修复计划

1. 先在现有布局门禁中锁定固定网格行与各层 `min-height: 0` 契约，并确认旧实现失败。
2. 将轨道行固定为 `minmax(0, 1fr)`，允许轨道、卡槽和面板在舞台高度内收缩。
3. 保持现有外框尺寸、圆角、分页点与手势逻辑不变，避免用继续增大卡片掩盖问题。
4. 验证资料卡首帧、资料→音乐滑动中、音乐页落位、反向切回和减少动态效果模式。

## 验收标准

- 资料卡静止时内面板四边和底部圆角完整可见。
- 音乐卡从第一帧进入到切换完成期间尺寸不变、底边不消失、页面不发生二次调整。
- 快速往返滑动不会改变卡片高度或裁切内容。
- 受影响 Vitest 门禁、Blog type-check、scoped lint 与构建通过。
