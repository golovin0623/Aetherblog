# 知识工作台产品化重构

> 选定方向：视觉方案 3（自然语言驱动），按用户反馈进行融合式重设计，不照搬概念图比例。
>
> ref: `docs/pm/atlas-redesign.md`、`.agent/plans/intelligent-notes-module-design.md`、`docs/output/11-aether-knowledge-atlas/`

## 1. 单一任务

目标用户是 AetherBlog 内容管理员。知识工作台的单一任务是：

> 用户用业务语言说明目标，系统带上正确内容，先回放将要执行的步骤与边界，再让用户试跑、验证引用并决定是否继续。

首个价值不以创建 KB、理解 Atlas 或搭建节点为完成，而以“得到一条可追溯、可验证的结果”为完成。

## 2. 视觉融合约束

### 2.1 既有 Aether Codex 调色板

不新增颜色，只消费现有 token：

- Void `#05060A` → `--bg-void`
- Substrate `#0B0D14` → `--bg-substrate`
- Leaf `#12141D` → `--bg-leaf`
- Raised `#1A1D28` → `--bg-raised`
- Ink `#F4EFE6` → `--ink-primary`
- Aurora `#818CF8` → `--aurora-1`

状态只使用 `--signal-success / warn / danger / info`。Aurora 只服务于当前选择、焦点和唯一主动作，不铺满所有表面。

### 2.2 字体角色

- 页面标题：现有 `.font-display`（Fraunces），只用于 H1。
- 操作与正文：项目现有 Geist Sans。
- 时间、数量、状态元数据：`.font-mono`（Geist Mono），不用于普通说明文。

### 2.3 密度与控件

- 桌面主按钮高度 40px；次按钮 36px；图标按钮 36px。
- 移动端触控目标不小于 44px。
- 页面最大内容宽度服从现有 AdminLayout，不创建全屏居中“大卡片应用”。
- 主区与上下文区在 `xl` 形成 `minmax(0, 1fr) + 320px`；小屏上下文进入可折叠区域/Bottom Sheet。
- 表面最多两层：页面底色 + leaf/raised 工作区；禁止 card-in-card 网格。
- 现有 Lucide 是 AetherBlog 的产品图标系统，继续使用，不引入第二套图标语言。

### 2.4 记忆点

唯一签名交互是“可编辑执行回放”：系统把自然语言目标翻译为 3–5 个业务步骤，当前步骤显示一条克制的 Aurora 轨迹。顺序本身承载真实执行含义，不作为装饰编号。

其余视觉保持安静；概念图中的大面积发光 CTA、巨型模式卡和重复描边全部缩减。

## 3. 自我审查与修正

原方案 3 的问题：

1. CTA 过大，像落地页转化按钮，不像后台操作。
2. 来源、模式、Prompt、步骤、边界与结果同时争夺注意力。
3. “发送箭头”“用示例试跑”“调整步骤”的先后关系不清楚。
4. 右栏重复展示上下文，没有明确可编辑入口与作用范围。
5. 视觉更像独立 AI 工具，没有充分继承后台已有按钮、面板、导航与密度。

修正后只保留一个主动作，并随状态更名：

- `compose`：**检查执行方案**
- `review`：**确认并进入灵境**

“调整来源”“修改目标或来源”始终是次动作，不与主动作同色、同尺寸。工作台不再伪造本地试跑或成功结果；它只负责让用户确认目标、来源与边界，然后将同一份上下文交给灵境的真实执行。持续、定期或触发式任务由“智能编排”单独承接。

## 4. 交互状态机

```text
compose
  ├─ 选择模式：提问求证 / 整理内容 / 一次检查
  ├─ 来源范围：自动选择 / 手动选择 / 不使用知识
  ├─ 输入目标
  └─ 检查执行方案
        ↓
review
  ├─ 回放系统理解
  ├─ 展示来源与过期/失败提醒
  ├─ 核对步骤与不可越过的边界
  └─ 确认并进入灵境
        ↓
AetherHub
  ├─ 预填同一目标与来源，不自动发送
  ├─ 由用户主动发起真实请求
  └─ 展示结构化检索回执与可回到原文的依据
```

## 5. 来源范围契约

必须保留三态，并在 Admin → Go → AI 每一层显式携带或校验 `knowledgeContextMode`，不再通过 ID 字段是否缺失猜测用户意图：

- `auto`：Go 只自动注入当前用户有权且可检索的知识库/Atlas 内容；无命中时可明确无私有依据地继续普通回答。
- `selected`：只使用明确选中的 KB/KP/Carrier，未选通道写入 `null`；关闭 Atlas 语义扩散与邻域扩展；全部无命中/不可用时发送检索回执和可重试错误，不调用模型。
- `none`：Go 强制 KB 与 Atlas 为 `null`，AI 层再次阻断私有检索，即使客户端传入矛盾字段也不放大权限。

Note 不伪装为聊天后端支持的 `noteIds`。笔记只在当前内容指纹、active profile、实际分块与 Markdown Carrier 全部一致时显示“可用于提问”；随后交接已验证的 `atlas-carrier`，只预填可编辑问题而不自动发送。

Handoff 采用用户隔离、10 分钟 TTL、一次性消费的 `sessionStorage`。它只运输 ID/短标签/意图/草稿，不承担授权；服务端权限检查仍为最终边界。

## 6. 信息架构

侧边栏 Intelligence 收敛为：

1. 知识工作台 `/intelligence`
2. 灵境 `/aetherhub`

Notes、Atlas、知识库、智能编排、写作助手、试卷拆题保留全部旧路由，在知识工作台任务入口、命令面板和搜索中可达；不删除深链，不强迫一次性迁移 URL。

## 7. 第一批实现

1. Intelligence 导航与路由单一事实源。
2. `/intelligence` 知识工作台，完成 compose → review → AetherHub 真实执行的核心状态机。
3. 自动/手选/禁用来源契约与一次性 Handoff。
4. Note、KB 与 Atlas Carrier/KP → 灵境上下文交接，且不自动发起付费请求。
5. KB 默认概览：添加资料 → 处理状态 → 试问；Profile/成员/迁移移入高级设置。
6. Workflow 默认从目标与模板开始；Canvas 保留为高级编辑。
7. 清除本范围原生 `<select>`，列表分页复用 `AdminPagination`。

## 8. 不伪造的边界

- 工作台不生成本地示例运行、伪检索或伪成功结果；真实执行只在灵境中由用户主动发起。
- Workflow capability 请求失败显示“能力状态未知”，不能回退为看似确定的默认能力清单。
- 本地草稿、模板、服务端工作流和生产运行统计不得混合。
- 尚未建立权限安全映射的 KB 文件不能显示“进入 Atlas 精读”的可用按钮。
- Handoff 只填充上下文与草稿，必须由用户主动发送；工作台的方案确认不会请求模型或修改线上内容。

## 9. 验收

- 1440×1024 与 390×844 可完成核心路径，无横向溢出。
- 主按钮在任一状态只有一个，动作名与结果一致。
- 来源三态的最终 JSON 语义有单测证明。
- Note/KB/KP Handoff 一次性消费，刷新不重复，撤权来源不静默替换。
- 所有 Select 可键盘操作，Dialog 关闭后焦点回到触发器。
- `pnpm --filter @aetherblog/admin test/typecheck/lint/build`、`pnpm design-system:check`、`git diff --check` 通过。
- 源图与实现同视口设计 QA 无 P0/P1/P2，`design-qa.md` 最终为 `passed`。
