## 2025-02-27 - Integer Overflow in uint64 to int64 Casts
**Vulnerability:** System or Docker statistics (such as memory limits) are often reported as `uint64` by APIs. When these values are directly cast to `int64` (e.g., `int64(val)`) without bounds checking, extremely large values (like `math.MaxUint64` which represents an unlimited limit in some cgroups versions) will overflow into negative values. This can corrupt memory tracking, metrics aggregation, and lead to potentially abusable application state (CWE-190/Gosec G115).
**Learning:** External or OS-level metrics, particularly from Docker/cgroups limits or system hardware stats, often use the maximum possible unsigned integer value to denote "unlimited" or "unrestricted" configurations. Direct unchecked type conversions are dangerous.
**Prevention:** In the Go backend, when converting `uint64` system or Docker statistics to `int64`, always explicitly bound the `uint64` values using `math.MaxInt64` (e.g., `if val > math.MaxInt64 { val = math.MaxInt64 }`) before casting to prevent integer overflow vulnerabilities.
